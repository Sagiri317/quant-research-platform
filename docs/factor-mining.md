# 自动化挖因子

自动挖因子的重点是让每一轮实验回答一个问题，再用结果决定下一轮做什么。Agent 负责提出假设和调用工具；公式求值、数据时间语义、评价和回测复用仓库实现。本轮不引入新的多 Agent 框架、向量数据库或搜索调度系统。

## 从本地数据开始

默认对话可以直接读取当前仓库。先用 `read` 查看 `AGENTS.md`、`data/`、`configs/prepare-source.json`，用 `search` 查找对应原生入口和因子定义。原始表、已实现因子和已计算因子是三回事：例如 `data/raw/csmar/` 存在但 `data/research/` 为空，只说明尚未在这里生成研究数据集，不能说没有本地数据。

CSV、Parquet 和 Excel 的 `read` 返回字段、结构、行数等元信息，不把金融数据明细发送给模型。字段含义还需要查供应商字段说明和适配器。真正的清洗、抽样统计和计算通过 `terminal` 在本机完成，反馈只打印计数、缺失率、时间范围、覆盖率、相关性和评价指标。私人原始行、凭据、供应商原始响应和异常回溯留在本机。

想知道已有因子时，先查 `interfaces/queries.py`、`markets/implementations/a_share/processed/` 以及数据集 `spec.json`。前者能说明已经实现哪些定义，后者能说明当前落盘数据实际有哪些列。可以通过项目 Python 调用 `list_factors` 获取目录，不需要为每个因子再注册一个 Agent 工具。

如果只有原始表，读取 `prepare`、`assemble` 的实际入口和配置示例，使用既有数据准备过程。不要直接把供应商原始字段当作已经满足复权、股票池、公告可用时间或标签成熟约定的研究面板。也不要为了出结果重新写一套简化的收益和时间对齐算法。

## 一次完整的研究

1. **盘点和假设。** 列出可用数据、已有因子、缺失条件，以及少量有经济解释、可证伪的新假设。只做这一步时，无需用户先填写完整回测协议。
2. **确定实验口径。** 计算前固定标签和预测期限、信息可用时间、股票池、训练/验证/测试窗口、比较基线、成本及有限候选预算。优先检查当前任务和项目已有设置，真正缺少的决定才询问用户。不能把文档示例日期当作本次研究日期。
3. **训练期迭代。** 提出一小批因果公式，检查算子、缺失、覆盖和与基线的重复程度；用训练期反馈决定改写、停止或丢弃。公式必须只依赖当时可获得的信息，禁止未来位移和将标签作为输入。负结果和未定义结果都保存。
4. **固定候选后选择。** 候选及超参数确定后，统一验证一次。反复看验证结果再改公式，就已经把验证集用于训练；已有查看记录不能靠改个名称变成新留出集。
5. **最终评价。** 固定选择及所有处理规则后，在未参与开发的测试期评价一次。检查 IC/RankIC、有效样本、不同时间段的稳定性、与已有因子的相关性和增量效果；有适用交易规则时继续做费用后组合或账户回测。报告所有约定窗口，不挑市场最好的单窗。

启动示例：

> 请直接检查本地 A 股数据和已有因子，先提出三个有经济解释的候选。不要跑全量数据，也不要查看测试期；列出能复用的数据准备入口和实际缺少的实验设置，等我补充后按有限预算继续验证。

已具备研究数据时：

> 使用已绑定的 source，沿用我指定的标签、训练/验证/测试窗口和交易成本，最多尝试 12 个候选。训练期反馈用于改写，固定候选后验证一次，测试只做最终评价；保留失败和未定义结果，比较已有因子的增量作用。没有有效候选也直接报告。

`terminal` 的工作目录是项目根目录。PowerShell 中用 `& $env:QRP_PYTHON ...` 调用当前项目解释器，`$env:QRP_OUTPUT` 是本次行动的新输出目录，`$env:QRP_WORKSPACE` 是仓库根目录。将脚本、配置和产物写入本次输出目录。后续用 `read` 的 `output:e0001/results/...` 读取它们，不需要将绝对路径发送给模型。命令返回退出码；超时和中断会清理本次拥有的进程树。

## 仓库已有的公式搜索能做什么

入口为 `research/factors/search.py` 的 `search_factors(config)`，CLI 为 `search-factors`。必须先阅读实际配置校验；可以参考 `configs/research-learning/agent.json` 中的配置形状，但不得复制其中的样本选择。

已有实现支持随机搜索、PPO 搜索，以及显式提供的 `expressions`。表达式通过 AST 白名单解释，没有使用 Python `eval`。支持加减乘除、取负、`abs`、`sign`、`logabs`、截面 `rank` 和正整数窗口的 `delay`、`mean`、`std`。每次搜索有候选预算、深度和随机种子；记录所有已评价候选，包括未定义结果。

其目标是**同一时点多资产之间的截面 RankIC**。`train_rank_ic` 是候选排序与标签排序的相关；`train_incremental_rank_ic` 是候选截面排名对已有基线排名做回归后的残差，与标签排名的相关。后者衡量一种增量关联，不等于已证明组合收益提高，也不等于模型组合后的 IC。

原生随机/PPO 的自适应反馈只用训练集；候选固定后计算验证结果并选择表达式。Agent 如果继续改写下一批候选，应只输出训练反馈，不向模型展示每一批的验证成绩。多轮迭代时，终端直接调用 `agents/mining.py` 的 `training_feedback(config)`：它复用现有 `formula_values`、`research_frame`、`mature_rows` 和截面统计函数，只加载训练窗口，返回训练 RankIC、增量 RankIC、覆盖率及每个公式的失败/未定义状态。接口不接受验证窗口或测试窗口。

这个函数的配置字段为 `dataset`、`columns`、`baseline_columns`、`label`、`train_window`、`train_cutoff`、`expressions`。`expressions` 必须是有限的字符串列表，窗口、成熟截止和特征列沿用本次研究设置。它不自动决定收益标签、成本或候选是否有经济价值。每一轮将返回值写入当前 `QRP_OUTPUT` 并打印同一聚合结果，供模型比较；最终合并固定候选，再调用一次 `search_factors`。这样可以保留真实实验反馈，而不用另写公式解释器或标签成熟逻辑。

选定结果可以通过 `apply_formula` 应用到后续窗口，它检查冻结时点并保留暖机历史。滚动算子当前按每资产的已观察行计算；这不自动等同于交易日历中的完整会话窗口，研究报告必须说明这一语义。高频存在 `segment_id` 时，公式滚动分组还会包含日期和交易段。

单只 ETF 的高频预测不能靠截面搜索得到有效结论。同一时刻只有一个资产时，截面排序相关无法定义；应复用 `evaluate-time-series`、高频特征和 `backtest-hft`，检查预测期限、交易段、库存及实际费用。把多个账户窗口拼接成一条收益曲线，或者平均它们的 Sharpe，都不是整体连续回测。

## 调研参考及取舍

[Microsoft RD-Agent](https://github.com/microsoft/RD-Agent) 及其[因子研究流程](https://rdagent.readthedocs.io/en/latest/scens/quant_agent_fin.html)将提出假设、编写实现、执行验证和分析反馈串成循环。适合借鉴的是反馈驱动的实验过程，而不是为了同样的过程引入整个外部框架或照搬它的历史数据设置。

[AlphaAgent](https://arxiv.org/abs/2502.16789)关注表达式复杂度和与既有因子的重复，[AlphaForge](https://arxiv.org/abs/2406.18394)把候选挖掘和动态组合分开，[基于 LLM 和 MCTS 的公式挖掘](https://arxiv.org/abs/2505.11122)使用量化反馈引导搜索，并避免反复探索相同子树。[FactorMiner](https://arxiv.org/abs/2602.14670)把经验反馈用于减少重复搜索。对当前仓库更直接的改进是明确基线、记录候选、减少重复、用正确样本反馈，而不是马上添加 MCTS 或更多 Agent。

本轮实现本地发现、通用执行、资料检索、图片/PDF 输入及研究流程指引，并保留原生搜索。尚未运行大规模私人数据挖掘 benchmark，也没有据此宣称发现了新的可盈利因子。下一步是否增加批量候选调度或搜索算法，应由真实实验中的失败比例、重复率、验证衰减和计算耗时决定。

## 当前问题和后续优先级

| 问题 | 当前处理 | 仍需怎样判断 |
|---|---|---|
| 能介绍研究方法，却找不到本地数据和源码 | 三个通用工具直接访问仓库，返回原始字段、目录和真实代码 | 私人数据的全量准备仍有实际计算成本，不在问答时自动重算全部历史 |
| 把提出假设也卡在完整协议前 | 数据盘点和假设先做，实验所需决定再确认 | 没有标签和时间选择时，不编造结果来填补 |
| 每轮公式改写都先计算并展示验证成绩 | `training_feedback` 只读取训练窗口；固定候选后再调用原生验证 | 通用终端具有本机权限，流程要求不等于访问隔离；若曾看过留出结果，必须披露 |
| 公式不合法、缺失过多、没有截面样本或与基线完全重合 | AST 白名单、成熟样本过滤、覆盖率、增量 RankIC、失败和未定义记录 | 不把“未定义”填成零，也不自动放宽标签、样本和评价轴 |
| 大量公式只是语法不同或高度相关 | 既有搜索对 AST 完全相同的候选去重，训练反馈可检查基线残差 | 还没有代数等价化、全因子库语义去重；先用简单相关性和新增信息判断，暂不引入大型记忆系统 |
| 高频目标与日频截面目标不一致 | 已有时间序列评价和高频回测可通过终端调用 | 尚未实现独立的高频公式优化器，不能把截面搜索改名后当作完成 |
| 因子 IC 高，却未必带来可交易收益 | 固定预测、交易规则和成本，再调用现有账户回测 | 仍需在真实样本检查换手、容量、库存和多窗口表现；合成验收只证明软件链路 |

下一轮低成本且有实验证据后值得做的改进，是将每次训练反馈中的候选、覆盖率和基线相关性整理为紧凑的可回读摘要，减少模型重复试同一思路。新的 MCTS、强化学习搜索、并行多 Agent 或长期经验数据库应晚于数据准备、评价口径与小规模真实因子实验；这些机制无法替代正确反馈。
