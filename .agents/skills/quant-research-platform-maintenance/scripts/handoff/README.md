# Handoff Scripts

This directory contains tracked QRP handoff tooling. Handoff packages must be
built and verified from these scripts, not inferred from `.run/` outputs.

## Files

```text
handoff_contract.py
receipt_contract.py
replay_evidence.py
build_handoff_package.py
verify_handoff_package.py
self_test.py
README.md
```

## Contract Owners

- `handoff_contract.py` owns the zip layout, sidecar schema, task metadata
  schema, artifact manifest schema, validation summary schema, `ProofClass`,
  validation row source contract, replay command contract, and evidence graph.
- `receipt_contract.py` owns exact receipt schemas, receipt field specs,
  receipt invariants, normalization, and replay comparison.
- `replay_evidence.py` runs public machine replay and returns canonical
  receipts, including hard-scan receipt payload construction from
  `governance_contract.source_tree_scan_groups()`. It does not define schemas,
  allowed keys, proof classes, validation rows, replay commands, or comparison
  rules.
- `verify_handoff_package.py` is the package-level trust boundary. It reads the
  sidecar, validates the zip envelope, validates exact member payloads, clones
  `final-branch.bundle`, checks task metadata Git identity, replays public
  receipts in the clone, compares packaged receipts to replayed receipts, and
  compares packaged validation summary to the replay-derived summary.

## Build Entry

The scripted build entry is:

```text
python .agents/skills/quant-research-platform-maintenance/scripts/handoff/build_handoff_package.py --repo-root . --out-dir .run/handoffs --task-name <task-name> --base-ref <base-ref> --mode evidence --verify
```

The builder reads current Git state, requires a clean worktree, computes
`base = git merge-base HEAD <base-ref>`, writes `final-branch.bundle`, runs
machine replay, writes canonical receipts, derives validation summary, writes
the manifest, zip, and external sidecar, then optionally runs the verifier.

The builder reads only current Git state and the documented CLI options; all
machine evidence is generated by replay.

## Package Layout

The zip contains exactly:

```text
artifact_manifest.json
final-branch.bundle
task_metadata.json
handoff_evidence/validation-summary.json
handoff_evidence/package-smoke-receipt.json
handoff_evidence/hard-scan-receipt.json
handoff_evidence/check-receipts.json
```

The external sidecar contains only:

```text
schema_id
zip_filename
zip_sha256
```

Task metadata contains only:

```text
schema_id
task_name
mode
branch
base
final_head
```

The verifier reads branch, base, and final head from `task_metadata.json`, not
from the sidecar.

## Receipt Rules

Receipt JSON payloads are exact-schema compact machine receipts. They must not
include raw stdout/stderr, raw grep output, full pytest logs, local install
paths, wheel/sdist files, or private/generated data.

`hard-scan-receipt.json` contains only `schema_id`, `status`, `scanned_head`,
`scanner_source_sha256`, and `scan_runs`. Each scan run contains only
`scan_id`, `rule_set_id`, `match_count`, `actual_violation_count`,
`result_sha256`, and `replayable_from_bundle`.

Validation summary is derived from replayed receipts and contains only:

```text
schema_id
rows
```

Each row contains only `name` and `status`.
